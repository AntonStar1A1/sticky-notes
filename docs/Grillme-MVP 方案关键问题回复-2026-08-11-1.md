## 第二轮：登录交互

**Q3: 登录界面用什么形式？**

选项：
- A: **弹窗 Modal** — 居中浮层，背景半透明遮罩
- B: **侧边面板** — 和设置面板一样，替换便签列表
- C: **新窗口** — 像便签一样，单独开一个 Tauri 窗口

考虑到你的 app 是桌面便签工具，窗口本身不大（大概 300x500），弹窗可能会很挤。
答： 侧边面板（复用设置面板模式）

**Q4: 登录表单需要哪些字段？**

- 邮箱 + 密码 + 登录按钮
- 还需要注册入口吗？（注册在网页端做？还是 app 内也能注册？）
- 需要"忘记密码"吗？
答：注册在网页端，点击注册弹出网页端首页；

## 第三轮：状态切换

**Q5: 登录成功后的过渡动画？**

- 直接刷新列表？
- 还是显示一个"同步中..."的加载状态？
答：显示"同步中..."loading

**Q6: 退出登录的入口？**

- 点击用户头像弹出菜单？
- 还是在设置面板里加一个"退出登录"按钮？
答：点击用户头像弹出菜单

**Q7: 用户头像显示什么？**

- 用户名首字母？（如 "A"）
- 还是邮箱首字母？
- 还是一个通用的用户图标？

## 第四轮：细节体验

**Q8: 登录时的加载状态？**

- 按钮变灰 + 文字变"登录中..."？
- 还是整个表单区域显示 loading？
答：按钮变灰 + 文字变"登录中..."

**Q9: 登录失败的提示？**

- 表单下方显示红色错误文字？
- 还是顶部 error banner（现有风格）？
答：表单下方红色文字

**Q10: 同步状态的文字怎么写？**

- `已同步` / `同步中...` / `离线`
- 还是更具体：`已同步 · 10:30` / `同步中 (3/100)` / `离线`
答：更具体：`已同步 · 10:30` / `同步中 (3/100)` / `离线`
