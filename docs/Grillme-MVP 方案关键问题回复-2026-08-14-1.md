  拷问清单:从用户角度,哪里不合理、反人类

  一、数据与隐私(会真丢东西、或隐私承诺落空)

  1. 「空便签关闭即删」分不清「新建没写」和「老便签被清空」——用户会永久丢失历史便签
  代码注释写的是"新建后未填写",但 NoteApp.tsx:366-377
  的空判定只有"当前是否全空",没有"是不是新建"的检查。用户把一张三个月前的便签内容清空(想重写、或 Ctrl+A
  误删)后关窗,discard_empty_note(main.rs:557-591)直接物理 DELETE,连这张便签的全部时间轴历史一起抹掉,回收站里都没有。
  - 交付报告 §六.9 声称"新建便签未填写不保存",但实现无法区分这两种场景,报告夸大了安全性。
  - 承诺的"软删除 30 天可恢复"恰恰在最惨的场景失效。
  - 建议:discard_empty_note 加一个门槛——只有 created_at 在几分钟内、且时间轴只有一条 create
  条目的才物理删除;老便签清空后关窗应走软删除进回收站。

  2. 时间轴是隐私分类的后门:锁定后标题、编辑历史、删除快照全文照样可见
  db.rs:682-705 的 get_all_timeline 没有任何隐私过滤;而 main.rs:442/499/528 在删除/彻底删除/自动清理时把便签全文写进
  note_snapshot。结果:隐私分类锁着,用户在时间轴点开"查看内容",把隐私便签的完整内容读出来——密码锁形同虚设。锁定后"仅显示
  密码框"的承诺(报告 §7.13)被时间轴绕开。
  - 建议:时间轴查询按 category_id 排除隐私分类条目(未解锁时),或对隐私便签的快照存脱敏占位。

  3. 捕获栏会把内容写进锁着的隐私分类,而且用户改不了
  CaptureApp.tsx:24-29 保存到 localStorage 的 lastActiveCategoryId,main.rs:312-325 的 save_capture
  不做隐私检查。用户上次选了隐私分类、锁定后按 Ctrl+Shift+Q
  记点东西,内容直接进锁定分类,而捕获栏只弱弱显示"保存到:隐私",没有改分类的入口。锁着的抽屉还在往里塞东西,逻辑自相矛盾。
  - 建议:捕获时若目标分类为隐私且锁定,弹密码输入,或回退到"默认"分类并 toast 告知。

  4. 隐私密码是单轮 SHA-256,拿到 DB 文件的人可离线爆破
  db.rs:110-114,salt 明文存在同库 meta 表。GPU 每秒几十亿次,六位数字密码秒破。虽然 UI
  诚实写了"视觉隐藏、明文存储",但"密码锁"三个字给用户的安全预期远高于实际。换 PBKDF2/argon2 是几行代码的事,成本极低。

  二、交互陷阱(高频、无征兆)

  5. 三个默认全局快捷键全是各大软件的常用热键——而且"冲突检测"永远检测不到
  Ctrl+Shift+V 是几乎所有编辑器/浏览器/Office 的"粘贴为纯文本",Ctrl+Shift+N 是 Chrome/Edge 的无痕窗口,Ctrl+Shift+Q
  关联浏览器关窗。全局热键无视焦点:用户在任何应用里按 Ctrl+Shift+V
  想贴纯文本,便签窗口会同时蹦出来建一张剪贴板便签。被动冲突检测救不了——浏览器根本不注册全局热键,检测永远静默。这个锅在
  spec(§7.11 定的默认值),实现忠实执行了。
  - 建议:默认改成高冲突不可能的组合(如 Ctrl+Shift+Alt+键),或默认禁用、首次启动引导自选。

  6. 滚轮悄悄改透明度:紧凑模式全窗无豁免区,纯色样式下滚轮像失灵
  NoteApp.tsx:509-525。QQ/微信式窗口滚轮是滚动内容的,这里在改透明度;紧凑模式没有任何"内容区豁免",用户误滚一下透明度就掉
  0.05,一路能打到 15%,全程无任何数值反馈。更糟的是 solid 样式在 noteBackground 提前 return,忽略
  opacity——滚轮转半天啥也没变,像 bug。
  - 建议:滚轮调透明度限定在标题栏区域;solid 样式下禁用并给提示;调整时 toast 显示当前透明度。

  7. IME 输入法误触 ×4:中文用户必然高频踩中
  CaptureApp.tsx:41-47(Esc)、CaptureApp.tsx:95-100(Enter)、PrivacyLock.tsx:82-84、TodoView.tsx:147 的 keydown 全部没有
  isComposing 判断。中文输入法选词时按 Enter 上屏或 Esc
  取消组词:捕获栏内容还没打完就保存了、或者整个窗口直接没了;设密码时打拼音回车直接提交半截。目标用户 100%
  中文输入,这是系统性缺陷。
  - 建议:所有 keydown 处理器统一加 if ((e.nativeEvent as KeyboardEvent).isComposing) return。

  8. 边缘吸附默认开启:窗口停靠屏幕边 0.3 秒就被"吃掉"
  useEdgeDock.ts:354-363 + setSkipTaskbar(true):280px 窄窗留一半在屏幕边缘是用户的自然操作,静止 300ms 后窗口被吞成 4px
  的缝,任务栏图标也消失。找回方式是把鼠标精确悬停在那条缝上——而缝的一半在屏幕外。永久 100ms 轮询还费电。QQ
  用户熟悉这个,普通用户只会以为应用消失了然后重开一个。
  - 建议:默认关闭;或首次吸附时 toast 告知"已吸附,鼠标移到屏幕边缘唤出";条加宽到 8px;吸附后不 skipTaskbar。

  9. 待办视图「+ 新增待办」复用最近更新的旧便签,违背 spec
  TodoView.tsx:110-126。spec 7.13 明确写"无待办便签时自动创建",实现却是找一张最近更新过的待办便签往里塞。用户以为在新建,
  任务实际进了另一张旧便签;且用户无法选择目标便签。报告 §7.13 打了 ✅,规格偏差未披露。
  - 建议:按 spec 自动创建新待办便签;或弹出目标选择器。

  10. 主题切换是盲盒循环,spec 自己内部矛盾
  App.tsx:62-67 的 cycleTheme 循环 6 种主题:看不到当前主题名,想换回上一个要盲点 5 次,自定义色不在循环里。spec §7.14
  写的是"点击弹出面板",§8.6 却写循环切换——spec 内部打架,实现选了差的那个。
