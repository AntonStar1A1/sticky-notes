## 一、时间轴

|------|---------|------|
| 新建便签 | ✓ | 记录标题快照 |

| 删除便签（进回收站） | ✓ | 记录标题快照 |
| 从回收站恢复 | ✓ | |
| 彻底删除 | ✓ | |
| 置顶/取消置顶 | ？ | 是否太琐碎？ |
| 修改颜色 | ？ | 是否太琐碎？ |
| 添加/删除附件 | ✓ | |
| 勾选/取消待办项 | ？ | 一条待办勾选一次就记一条？会很多 |



**Q1: 编辑操作的粒度？**

- A: 只记录"修改了「标题」"，不记录具体改了什么

- C: 记录完整快照，可以查看修改前的内容
答：记录具体字段变化，如"标题从 AAA 改为 BBB"

**Q2: 勾选待办项要记录吗？**

如果用户有 20 个待办项，勾选一次记一条，时间轴会很嘈杂。

- A: 记录，但默认折叠/隐藏
- B: 不记录，只记录便签级别的操作
- C: 只记录"全部完成"这种里程碑
答：记录，但默认折叠/隐藏

- A: 顶部横向筛选栏（类似标签页）
- B: 右上角下拉菜单

### 1.3 展示方式

**Q5: 编辑操作要不要显示具体改了什么？**

```
方案 A：简洁

         │ 内容: (空白) → 今天讨论  │
         └─────────────────────────┘
```

**Q6: 已删除的便签在时间轴里怎么展示？**

**Q7: 时间轴太长怎么办？**

### 3.3 加密范围

**Q21: 加密什么？**

```
方案 A：UI 级别锁定
  数据在 SQLite 中是明文的，只是界面需要密码才能查看
  简单实现，但安全性较低

方案 B：数据级别加密
  便签内容在 SQLite 中是加密的（AES），密码是解密密钥
  安全性高，但密码丢失数据就没了
```
答：方案 A：UI 级别锁定

**Q22: 隐私分类的便签同步到云端吗？**

- A: 同步，但云端也是加密的
- B: 同步，云端明文（安全性低）
- C: 不同步，仅本地存储
答：B: 同步，云端明文（安全性低）

**Q23: 隐私分类可以有多个吗？**

- A: 只有一个内置「隐私」分类
- B: 用户可以创建多个加密分类，共用一个密码
- C: 用户可以创建多个加密分类，每个分类独立密码
答：A: 只有一个内置「隐私」分类
