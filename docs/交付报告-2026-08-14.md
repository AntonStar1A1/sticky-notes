## 三、已知限制(如实说明)

1. **Windows 文本拖拽创建**:wry 在 Windows 上只放行 HDROP(文件)拖放,浏览器/其他应用的文字、URL 拖入**不被系统放行**。HTML5 文本拖放处理器已保留,该能力在支持文本拖放的平台(如 macOS)可用;Windows 上拖拽创建可用「文件拖入」(生成路径列表便签)。这是平台限制,非代码缺陷。
2. **检查更新/用户协议**:设置面板「关于」页暂无「检查更新」「用户协议/隐私政策」入口——无后端更新源、无现成协议文档,避免造假入口。
3. **登录/同步/Token**:整体范围外(需 Toolbox)。
4. **待办视图「各自滚动位置」**:便签/待办切换时滚动位置未分别记忆(小体验项,列表整体滚动)。

## 四、冒烟测试透明度说明

冒烟测试期间 `tauri dev` 曾尝试用 APPDATA 环境变量重定向数据目录,但 Windows 的 `dirs` crate 走已知文件夹 API、忽略该环境变量,导致开发实例**迁移了真实本地数据库**(v2→v3 迁移,32KB→53KB)。
- 迁移本身经过专门测试验证(`migrate_real_backup_db` 单测:对备份文件执行同一迁移,断言 schema_version=3、便签数不变、无 NULL uuid、隐私分类存在、新表齐全)。
- 迁移是数据保留式的;备份文件(启动前由你手动复制)未受影响。
- 若需回退:退出应用 → 用备份覆盖 `%APPDATA%\com.stickynotes.app\sticky_notes.db` → 重新启动。

## 五、子代理交叉检查修复清单(3 项阻塞缺陷 + 全部规格偏差)

独立子代理复核产出的 24 项细化清单已全部处理,其中:

**阻塞缺陷(3)**:

1. **create_note 死锁**(带分类新建必死):`std::sync::Mutex` 不可重入,`create_note` 持有 db 锁后又调 `category_name_of` 再次加锁 → 改用已持有连接直接查询 `db::get_category_name`,删除多余函数。修复后 cargo test/clippy 全绿,新建带分类便签正常。
2. **失焦锁定销毁隐私便签窗口**:原实现在 `onFocusChanged` 失焦即锁定,点开隐私便签窗口立刻被销毁。改为**仅最小化锁定**:Rust 检测最小化(tao 在 Windows 上最小化触发 `Resized(0,0)`;另以失焦 + `is_minimized()` 兜底)后 emit `main-minimized`,前端监听后执行锁定;普通失焦不再锁定。(修复中发现上一版检测代码用了 tauri 2.11 不存在的 `Size::Minimized` 变体,已替换,现可编译。)
3. **分类拖拽冒泡误建垃圾便签**:分类排序拖拽冒泡到 window 级 drop → 误建成文本便签。新增 `internalDragRef` 守卫 window 级 dragover/drop,卡片拖拽与分类拖拽全程置位/复位,分类 `onDrop` 增加 `stopPropagation`。

**规格裁决**:

4. **移除管理台内联编辑**(spec 7.10「保持独立窗口编辑(不改为内联编辑)」):卡片点击改为打开便签窗口;顺带消除了内联编辑的陈旧快照覆盖风险;卸载 flush 机制(原为内联编辑兜底)随之移除。待办视图的内联编辑属 spec 7.13 明确要求,保留。

**数据语义**:

5. **`permanently_deleted` 状态 + `deleted_by` 语义**(spec 881-887/1036-1042):彻底删除由物理 DELETE 改为标记 `status='permanently_deleted'`(行保留、不同步、用户不可见),`deleted_by='user'`;自动清理标记 `deleted_by='auto_clean'`;回收站(trashed)`deleted_by` 保持 NULL;`get_all_notes` 排除该状态;附件/待办随彻底删除立即物理清理;前端 `NoteStatus` 类型与 db 单测同步更新。

**UI 细节批量**(清单 14-22):

6. 标题栏「便签管理」→「便签」(spec 1467);卡片 8px 圆角 → 4px、内边距 8px 12px、悬浮态 rgba(255,255,255,0.04) 0.15s;时间行新增分类标签(品牌色胶囊);分类栏图标统一(全部 LayoutGrid/用户 Folder/时间轴 Clock);标签切换改纯文字 + 品牌色下划线;主题色值按 spec 1449-1461(品牌色 #4C9EEB、暗色 bg 0.85、亮/淡蓝/淡紫/淡黄背景值);收起态不显示时间、摘要最多 4 行;捕获动画统一 200ms;URL/邮箱检测无选中时从全文回退提取;附件右键删除;时间轴待办勾选/取消条目默认折叠、点击展开。

## 六、界面问题修复(用户反馈 4 项 + 后续修复 3 项,2026-08-14)

均为真机(WebView2 CDP)逐项取证、定位根因、修复后同一环境复验:

1. **分类栏拥挤挤压「全部」**:根因是 `.category-bar` 固定高度 flex 列内 `.category-item/.category-tool/.category-sep` 默认 `flex-shrink:1`,分类一多就压缩高度而不是滚动——项内图标被压到 5px、文字 5px、底部工具按钮 24px→13px、分隔线消失。修复:所有分类栏子项及项内图标/名称/计数 `flex-shrink:0`,改由滚动承载。复验:12/25 个分类下「全部」保持 53px 自然高度、图标 13px、工具按钮 24px、分隔线可见、栏可滚动。
2. **搜索右侧 + 被挤出窗口**:根因是 `.search-box-wrap`(flex:1)未设 `min-width:0`,输入框固有宽度(~180px)撑住不收缩,工具栏溢出 42px,「+」右缘 290px 超出 280px 窗口、导出按钮完全在外。修复:补 `min-width:0`(`.timeline-search` 同理预防)。复验:280px 及缩到 200px 均无溢出,全部按钮在窗口内。
3. **「已打开」不更新**:根因是便签窗口 × 为隐藏而非销毁,原列表按窗口存在统计,隐藏后仍显示;且 Rust 侧 `show()` 经主线程派发,管理器立即刷新会读到「尚未可见」。修复:列表只统计可见窗口(`get_open_note_ids` 过滤 `is_visible`);NoteApp 隐藏成功后 emit `note-window-hidden`、Rust `CloseRequested` 隐藏路径同步 emit;Rust `open_note` show 后延迟 400ms emit `note-window-shown`(沿用 highlight 重试思路);管理器监听两个事件刷新。复验:打开→出现、×→消失、再点卡片(复用隐藏窗口)→再出现,完整闭环。
4. **时间轴无返回按钮**:时间轴工具栏新增「← 返回」按钮,点击回到便签列表。复验:进入时间轴可见、点击后返回便签列表。

5. **重复分类(测试遗留数据清理)**：数据库中两组完全相同的空分类(工作/生活/学习/灵感 ×2、默认 ×2,共 9 个,均为 0 条便签)为早期界面测试遗留。经应用自身 delete_category 命令删除重复的 5 个(id 500-504),保留每个名字一个 + 系统隐私分类;验证无孤儿便签引用。
6. **便签窗口打开闪烁过多**：新建窗口 highlight 重试 3 次 emit × CSS 动画 3 拍,最坏 9 下连环闪。修复:NoteApp 侧 1.2 秒内去重(重试保留,慢加载仍保证至少闪一轮)+ 动画减为 2 拍。复验:模拟 3 次重试只闪 1 轮;点「已打开」定位窗口只闪 1 轮。
7. **启动时莫名多出重复分组**：根因是 v3 迁移为支持「重命名撞名」刻意删除了 `categories.name` 的 UNIQUE 约束,而 `init_db` 的默认分类播种仍是 `INSERT OR IGNORE`——没有 UNIQUE 就没有冲突可忽略,**每次启动都无条件插入 5 个默认分类**(线上复现:5 个默认名各 4 份,共 21 个分类)。修复:播种改为按名称存在性判断(`INSERT … SELECT … WHERE NOT EXISTS`,逐名判断);删除已产生的 15 个重复分类(经审计均无便签引用,删除前备份 DB);新增回归测试覆盖「init_db 反复执行 / 迁移后执行不重复、删除默认分类后重启恢复缺失默认名」。复验:cargo test 15/15;修复后应用连续两次重启,分类保持 6 个、零重复。
8. **「全部」视图便签多时被挤压、显示效果与分组不一致**：根因是 `.note-list` 为定高 flex 列,`.note-card` 默认 `flex-shrink:1`,且卡片三行文字都是单行省略(nowrap),卡片最小内容高度仅约 29px;便签一多,flex 把每张卡压缩到最小高度硬塞进可视区,scrollHeight 与 clientHeight 相等导致**无滚动条**(实测:14 张卡全被压到 29px)。分组内便签少、塞得下,看起来就成了「两种显示效果」。修复:`.note-card` 加 `flex-shrink:0`,由列表滚动承载;同类隐患一并加固(`.pinned-sep`、`.list-empty`、`.trash-card`、`.timeline-entry`、`.todo-section`、`.todo-row`)。复验:「全部」14 张卡恢复 78px 自然高度(标题/内容/时间三行与分组完全一致)、scrollHeight 1182>496 出现滚动条、scrollTop 滚动正常;空分组正常显示空状态。

## 七、便携模式(数据目录随 exe 走,2026-08-14)

用户担心免安装版放 D 盘、数据却落在 C 盘。经查 tauri 2.11.5 源码(`src/path/desktop.rs`),`app_data_dir()` 固定解析为 `{FOLDERID_RoamingAppData}\com.stickynotes.app`(即 `C:\Users\<用户>\AppData\Roaming\com.stickynotes.app`),与 exe 所在盘无关,且该版本无内置便携模式支持。为此实现应用层便携模式:

- **机制**:exe 目录下存在 `portable.txt` 标记文件(空文件即可)→ 数据目录 = exe 旁的 `data\`;无标记 → 回落 AppData(行为与之前完全一致)。标记文件由用户自行创建/删除,应用不代劳。
- **覆盖范围**(main.rs 全部 3 处数据落盘点):`sticky_notes.db` + `device_id`(setup)、`sync_queue.json`(离线队列)、`shortcuts.json`(快捷键配置)。导出 txt/csv 为用户自选路径,不涉及。核心逻辑拆为纯函数 `resolve_data_dir` 便于测试。
- **验证**:单元测试 3 个(有标记 → `exe\data\`;无标记 → AppData;exe 目录不可得 → AppData),cargo test 14/14、clippy 0 警告。真机复验:release exe 旁放 portable.txt 启动 → `data\sticky_notes.db` 与 `device_id` 自动生成在 exe 旁,AppData DB 未被触碰;无标记启动 → 不生成 data\ 目录,照用 AppData DB。
- **用法**:免安装版想数据随身,把 `sticky-notes.exe` 和空的 `portable.txt` 放同一文件夹即可;删掉 `portable.txt` 恢复默认。安装版不受影响(除非手动在安装目录放标记文件)。
