# 便签应用架构重构:独立便签窗口 设计文档

日期:2026-08-09
状态:已获用户分节确认,待文档审阅

## 1. 背景与问题

现状(方案 A 之前的架构):所有便签是主窗口(1200×800 透明置顶)内的绝对定位 div。三个根本缺陷:

1. **便签被锁死在主窗口边界内**——div 物理上无法离开宿主窗口
2. **便签随主窗口关闭而消失**——关闭管理器(隐藏)时便签不可见
3. **透明主窗口挡住下层应用**——OS 透明不改变鼠标命中,整个矩形区域吞掉输入;`set_ignore_cursor_events` 是整窗开关,无区域级点击穿透,"大透明桌面层"路线在 Tauri 里是死路

结论:每张便签必须是**原生窗口**,不是窗口里的元素。与 Windows 便笺、真实桌面便签应用的形态一致。

## 2. 已确认的关键决策

| 决策点 | 结论 |
|---|---|
| 主窗口角色 | 保留为**管理器**:分类、便签列表、搜索、新建;**双击条目聚焦对应便签窗口** |
| 编辑形态 | 便签窗口**就地编辑**;双击切换**紧凑 ↔ 展开**两种尺寸 |
| 便签规模 | 随用随建,不设池化/上限,不做资源回收策略 |
| 置顶语义 | 新建便签**默认置顶**,可个别关闭(复用 `is_pinned` 字段) |
| 实现路线 | 方案 A:每张便签 = 一个独立 WebViewWindow |

## 3. 窗口模型

| 窗口 | 标签 | 形态 | 职责 |
|---|---|---|---|
| 管理器 | `main` | 普通窗口(有边框、不透明、不置顶),1200×800 | 分类、便签列表、搜索、新建 |
| 便签 | `note-<id>` | 无边框、透明、默认 240×200,按 `is_pinned` 置顶 | 每张**打开**的便签一个,统一加载 `note.html?id=<id>` |
| ~~置顶列表~~ | `pinned` | — | **删除**,职责被管理器 + 便签窗口吸收 |

**生命周期(全部 Rust 侧驱动):**

- 新建便签 → 插 DB 行 → 建窗口 `note-<id>`(**展开态、聚焦**)→ 广播 `notes-updated`
- 新建便签窗口落在**鼠标所在显示器中央附近**(级联偏移),保证抬手可见
- 删除便签 → 销毁窗口 → 删 DB 行 → 广播
- 便签 × 关闭 → 仅 hide(窗口与 DB 保留,可从管理器/托盘再打开)
- 打开便签/管理器 → 窗口不存在则创建,存在则 `show + focus`

**配套:**
- vite 增加第三个入口 `note.html`(仿 pinned.html 模式)
- capabilities 的 `windows` 字段加 `"note-*"` 通配,权限覆盖:start-dragging / set-size / set-always-on-top / show / hide / close / set-focus(现有权限集已覆盖大部分)
- 便签 x/y/width/height/is_pinned 语义从"主窗口内坐标"变为"屏幕坐标"

## 4. 便签窗口交互(紧凑 ↔ 展开)

同一窗口两种状态切换:

**紧凑态(默认):** 240×200 透明小窗。显示标题 + 内容摘要(文字:前几行;待办:前 3 条 + 剩余计数)。只读。交互:标题区拖拽、右下角缩放(最小 180×120)、右键菜单、双击卡片任意处 → 展开。

**展开态(编辑):** 窗口放大至 360×420,**以左上角为锚点,位置不跳**。完整编辑控件:标题输入 + 正文 textarea(文字)或待办清单(勾选/增删/编辑)。右上角收起按钮;失焦/收起时保存。

**收起目标尺寸固定为 240×200**(用户手动缩放不记忆,展开会覆盖当前尺寸;决策记录:固定档位,行为可预期)。

**新建即展开:** 新创建的便签窗口初始为**展开态 + 自动聚焦**,光标可直接输入(贴近"随手记"体验);双击/收起按钮回到紧凑态。

**窗口级交互(两态通用):**
- 标题区左键拖拽 `startDragging`;右下角 resize 手柄,最小 180×120
- 右上角按钮:置顶开关 📌、收起/展开、关闭 ×(隐藏)
- 右键菜单:置顶开关、删除、透明度滑块、收起/展开
- 置顶关闭后窗口沉到其他应用后面(普通窗口行为)

**保存:** 每窗口独立 300ms 防抖 + 失焦/收起/卸载 flush,沿用现有模式;**编辑不广播**。

**透明度:** 紧凑态移除 footer 滑块,仅保留右键菜单控制,对两态生效;新建默认 `opacity = 1`(紧凑卡片背景透明由 CSS 实现,不再是整窗不透明度)。

## 5. 管理器窗口(`main`)

- 普通窗口,关闭=隐藏。布局沿用侧边栏(分类)+ 主区域,**主区域改为便签列表**
- 列表项:标题、类型图标(📝/☑)、内容摘要、更新时间、置顶标记 📌、所属分类
- 双击条目 → 聚焦对应便签窗口(已隐藏先 show),边框高亮闪烁 ~1.5s
- 行内操作:删除、置顶开关
- 顶部搜索框:按标题/内容实时过滤
- 新建按钮:+ 文字便签 / + 待办(与托盘菜单共用 Rust command)
- 分类侧边栏沿用现有 categories 表,列表按分类过滤

**刷新策略(防止性能问题回潮):**
- 打开/激活管理器时强制拉一次全量(`get_notes` + `get_all_todos`)
- 常驻监听 `notes-updated`(增删/置顶已广播)→ 全量刷新
- 便签编辑不广播,靠"打开时强制刷新"兜底

## 6. 数据与迁移

- 表结构不变(categories / notes / todo_items);新增 `meta` 表记录 `schema_version = 2`
- **v1 → v2 迁移**(首次运行新版执行一次):所有便签 x/y 重置为屏幕级联位置(100 + 按 id 排序的序号×40),宽高 240×200;`is_pinned` 语义不变;分类数据保留
- 新建便签默认值:`is_pinned = true`、`opacity = 1`、分类保持"无分类"、屏幕级联位置

**移除置顶列表窗口:** 删除 `show_pinned_window` command、pinned.html、PinnedApp.tsx、pinned.css、vite pinned 入口;托盘菜单重构为:**显示管理器 / 新建文字便签 / 新建待办 / 退出**。

**事件语义:** `notes-updated` 仅增、删、置顶变化时广播;编辑静默落库;窗口标签 `note-<id>` 幂等(已存在 → show + focus)。

**未来同步预留(决策记录):**
- 数据层以 db.rs 为唯一出入口;未来同步通过 HTTP 与服务器交互,桌面端不直接连接服务器数据库(服务器 DB 选型与桌面端无关)
- `updated_at` 已在表中,作为增量同步锚点
- `uuid` / `deleted_at`(软删除)等到同步功能立项时再加,通过 meta 版本号做 schema 迁移
- 冲突策略到时用"按 updated_at 后写者胜",现在不设计

## 7. 生命周期与错误处理

- 托盘"退出" → 进程结束;数据已实时落库,每便签窗口 blur + beforeunload flush 兜底。已知权衡:300ms 防抖窗口内的最后输入理论上可能丢失(用户点击托盘/其他应用时已失焦 flush,概率极小)
- 窗口创建失败 → command 返回错误,管理器提示;DB 错误沿用 `Result<_, String>` 模式
- 迁移失败 → 启动即失败,控制台报错,提示重建数据文件(个人工具,不做恢复 UI)

## 8. 手工验证清单

1. 新建便签 → 独立小窗口出现(展开态、聚焦、鼠标所在显示器中央),可拖出管理器边界、拖到屏幕任意位置
11. Ctrl+Alt+N / Ctrl+Alt+T 在任何应用内呼出新建便签
2. 关闭管理器 → 便签存活;托盘"显示管理器" → 回来
3. 管理器双击条目 → 便签聚焦并高亮闪烁
4. 紧凑 ↔ 展开:尺寸正确、位置不跳
5. 打字 300ms 防抖落库;重启数据完整
6. 删除便签 → 窗口销毁 + DB 删行
7. 升级迁移:旧便签位置重置为屏幕级联,分类保留
8. 置顶开关关闭后,便签沉到其他应用窗口后面
9. 待办便签:紧凑态前 3 条,展开态完整编辑
10. 托盘菜单四项全部可用

## 9. 全局快捷键与范围控制

**全局快捷键(本次纳入实现):** Ctrl+Alt+N 新建文字便签 / Ctrl+Alt+T 新建待办(任何应用内可用),依赖 `tauri-plugin-global-shortcut`;与其他应用冲突时提示注册失败。

**明确不做(范围控制):**

- 便签内容全文搜索(仅标题/摘要过滤)
- 多显示器位置记忆
- 数据导入导出
- 服务器同步(预留接口与字段,不实现)
